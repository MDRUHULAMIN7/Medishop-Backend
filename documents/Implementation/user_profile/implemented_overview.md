# MediShop User Profile & User Management Implementation Overview

এই ডকুমেন্টটিতে MediShop-এর ব্যাকএন্ডের **ইউজার প্রোফাইল (User Profile)** এবং **ইউজার ম্যানেজমেন্ট (User Management)** মডিউল কীভাবে কাজ করে তা বাংলায় বিস্তারিত আলোচনা করা হয়েছে। নতুন কোনো ডেভেলপার বা যে কেউ যাতে প্রজেক্টের ইউজার ডেটা স্ট্রাকচার, অ্যাড্রেস ম্যানেজমেন্ট, অ্যাভাটার/প্রোফাইল পিকচার হ্যান্ডলিং এবং অ্যাডমিন ব্লক/আনব্লক সিকিউরিটি মেকানিজম এক নজরে খুব সহজে বুঝতে পারেন, সেজন্য এটি তৈরি করা হয়েছে।

---

## ১. ওভারভিউ (High-Level Overview)

MediShop অ্যাপ্লিকেশনে ইউজারের নিজস্ব প্রোফাইল পরিচালনা এবং অ্যাডমিন কর্তৃক ইউজার নিয়ন্ত্রণের জন্য একটি শক্তিশালী সিকিউর আর্কিটেকচার বাস্তবায়ন করা হয়েছে। 

মূল বৈশিষ্ট্যসমূহ:
1. **প্রোফাইল তথ্য আপডেট (Profile Updates):** ইউজারের নাম, ইমেইল, ফোন নম্বর এবং অ্যাভাটার/প্রোফাইল পিকচার।
2. **প্রোফাইল পিকচার সাইজ লিমিটেশন (Avatar Size Limits):** পিকচারের স্ট্রিম/ইউআরএল সর্বোচ্চ **5MB** পর্যন্ত অনুমোদন করা হয়।
3. **মাল্টিপল শিপিং অ্যাড্রেস (Multiple Shipping Addresses):** একাধিক ডেলিভারি ঠিকানা যোগ, এডিট, ডিলিট এবং ডিফল্ট ঠিকানা নির্বাচন।
4. **অ্যাডমিন ইউজার স্ট্যাটাস কন্ট্রোল (User Block/Unblock Security):** অ্যাডমিন চাইলে যেকোনো ইউজারকে সাময়িকভাবে বা স্থায়ীভাবে `blocked` করতে পারেন।
5. **অটোমেটিক সেশন রিবোকেশন (Immediate Session Revocation):** কোনো ইউজার ব্লক হলে তার সকল অ্যাক্টিভ সেশন ও রিফ্রেশ টোকেন সাথে সাথে বাতিল বা মুছে ফেলা হয়।

## ২. ইউজার ডাটা মডেল (User Model Schema)

ডাটাবেজে ইউজারের নিম্নোক্ত ফিল্ডসমূহ সংরক্ষণ করা হয়:

| ফিল্ডের নাম | টাইপ | বর্ণনা |
|---|---|---|
| `name` | String (Required) | ইউজারের পূর্ণ নাম |
| `email` | String (Unique, Sparse) | ইমেইল এড্রেস (ছোট হাতের অক্ষরে নরম্যালাইজড) |
| `phone` | String (Unique, Sparse) | বাংলাদেশের মোবাইল নম্বর (স্পেস ও ড্যাশ ছাড়া) |
| `password` | String (Selected: false) | bcrypt হ্যাশকৃত সিকিউর পাসওয়ার্ড |
| `role` | String (Enum) | `customer`, `pharmacist`, `sales_staff`, `inventory_manager`, `admin` |
| `avatar` | String (Nullable) | প্রোফাইল পিকচারের URL বা সাইজ লিমিটেড ডেটা (Max 5MB) |
| `status` | String (Enum, Default: `active`) | ইউজারের অবস্থা: `active` অথবা `blocked` |
| `isVerified` | Boolean (Default: `false`) | ওটিপি ভেরিফিকেশন স্ট্যাটাস |
| `addresses` | Array of Address Schema | ইউজারের শিপিং ঠিকানার লিস্ট |
| `lastLoginAt` | Date (Nullable) | সর্বশেষ লগইনের সময় |

## ৩. প্রোফাইল ও অ্যাড্রেস ম্যানেজমেন্টের ধাপসমূহ (Profile & Address Flow)

### ধাপ ১: নিজের প্রোফাইল দেখা ও আপডেট করা (`GET/PATCH /users/me`)
- ইউজার তার অ্যাকাউন্টে লগইন থাকা অবস্থায় `/users/me` এনপয়েন্টে তার প্রোফাইল ডেটা রিড করতে পারে।
- প্রোফাইলে নাম, ইমেইল, ফোন বা অ্যাভাটার ছবি পরিবর্তন করতে `PATCH /users/me` রিকোয়েস্ট পাঠানো হয়। 
- Zod ভ্যালিডেশন দ্বারা নিশ্চিত করা হয় যে অ্যাভাটার স্ট্রিপ/ইমেজ সাইজ ৫ মেগাবাইটের বেশি নয়।

### ধাপ ২: শিপিং অ্যাড্রেস ম্যানেজমেন্ট (`/users/me/addresses`)
ইউজার তার অর্ডারের সুবিধার্থে একাধিক ডেলিভারি এড্রেস সেভ করে রাখতে পারে:
* **নতুন অ্যাড্রেস যোগ করা (`POST /users/me/addresses`):** গ্রহীতার নাম, ফোন, বিভাগ, জেলা, থানা, ও বিস্তারিত এড্রেস দিলে এড্রেসটি যুক্ত হয়। প্রথম এড্রেসটি স্বয়ংক্রিয়ভাবে `isDefault: true` হিসেবে সেট হয়।
* **এড্রেস আপডেট করা (`PATCH /users/me/addresses/:addressId`):** নির্দিষ্ট এড্রেসের যেকোনো ফিল্ড আপডেট করা যায়।
* **ডিফল্ট এড্রেস পরিবর্তন (`PATCH /users/me/addresses/:addressId/default`):** নির্দিষ্ট একটি এড্রেসকে প্রাইমারি/ডিফল্ট বানাতে এই এনপয়েন্ট ব্যবহার করা হয়। বাকি এড্রেসগুলো স্বয়ংক্রিয়ভাবে `isDefault: false` হয়ে যায়।
* **এড্রেস ডিলিট করা (`DELETE /users/me/addresses/:addressId`):** এড্রেস মুছে ফেলা যায়। ডিফল্ট এড্রেস মুছে ফেললে লিস্টের পরবর্তী এড্রেসটি অটোমেটিক ডিফল্ট হয়ে যায়।

## ৪. অ্যাডমিন ইউজার ম্যানেজমেন্ট ও সিকিউরিটি ব্লক মেকানিজম (Admin User Block Security)

অ্যাডমিনদের জন্য পুরো ইউজার লিস্ট দেখা এবং যেকোনো ক্ষতিকর বা ভুয়া অ্যাকাউন্ট ব্লক করার পূর্ণ ক্ষমতা রয়েছে।

### ১. সকল ইউজার লিস্ট দেখা (`GET /users` - Admin Only)
- অ্যাডমিন `/users` এনপয়েন্ট ব্যবহার করে সব রেজিস্টার্ড ইউজারের তালিকা দেখতে পারেন।
- **ফিল্টারিং ও সার্চ:** পেজিনেশন (`page`, `limit`), স্ট্যাটাস ফিল্টার (`status=active` বা `status=blocked`), রোল ফিল্টার (`role=customer`) এবং নাম/ইমেইল/ফোন দিয়ে সার্চ (`search=rahim`) করা যায়।

### ২. ইউজার ব্লক বা আনব্লক করা (`PATCH /users/:userId/status` - Admin Only)
- অ্যাডমিন যদি কোনো ইউজারকে ব্লক করেন (`status: 'blocked'`), ব্যাকএন্ডে দুটি অ্যাকশন এক্সিকিউট হয়:
  1. ইউজারের ডাটাবেজ ডকুমেন্ট ফিল্ড `status` আপডেট হয়ে `'blocked'` হয়ে যায়।
  2. **সেশন রিবোকেশন:** ব্যাকএন্ড `authRepository.revokeAllRefreshSessions(userId)` কল করে ওই ইউজারের রেডিসে (Redis) থাকা সমস্ত অ্যাক্টিভ রিফ্রেশ সেশন হ্যাশ সাথে সাথে ডিলিট করে দেয়।

### ৩. ব্লকড ইউজারের সিকিউরিটি এনফোর্সমেন্ট (Blocked User Enforcement)
যদি কোনো ইউজার `blocked` অবস্থায় থাকে:
- **লগইন চেষ্টা:** `/auth/login` রিকোয়েস্ট করলে সিস্টেম সাথে সাথে HTTP 403 Forbidden সহ `ACCOUNT_BLOCKED` এরর কোড রিটার্ন করে ("Your account has been blocked by an administrator.")।
- **টোকেন রিফ্রেশ চেষ্টা:** কোনো এক্টিভ সেশন দিয়ে টোকেন রিফ্রেশ করতে গেলে সেশন বাতিল হয়ে যায় এবং `ACCOUNT_BLOCKED` এরর দেয়।
- **প্রোফাইল/এপিআই রিকোয়েস্ট:** `/auth/me` বা যেকোনো প্রটেক্টেড এপিআই অ্যাক্সেস বন্ধ হয়ে যায়।

## ৫. সিকিউরিটি ডিজাইন নীতি (Security Best Practices)

* **পাসওয়ার্ড গোপনীয়তা:** ডাটাবেজ কোয়েরিতে `select: false` করা আছে এবং `toJSON` ট্রান্সফর্মে পাসওয়ার্ড ফিল্ড স্বয়ংক্রিয়ভাবে রিমুভ হয়ে যায়।
* **ইনপুট ডাটা নরম্যালাইজেশন:** ইমেইল এড্রেস সবসময় ট্রিম ও লোয়ারকেস এবং ফোন নম্বর থেকে স্পেস বা ড্যাশ ট্রিম করে ডাটাবেজে রাখা হয়।
* **অবজেক্ট আইডি ভ্যালিডেশন:** Mongo ObjectId এর সঠিক ফরম্যাট নিশ্চিত করতে Zod প্যারামস ভ্যালিডেশন হ্যান্ডলার ব্যবহৃত হয়।
